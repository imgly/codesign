# Handbook quirks — cryptic errors, runtime symptoms, diagnosis order

The handbook's quirk reference. CE.SDK errors are short and opaque. Two tables — error-message → cause, and runtime-symptom → workaround. Check both before bisecting; look up a fragment of the error message in them.

## Cryptic errors

| Error                                                              | Cause                                                                                                                         | Fix                                                                                                                                                        |
| ------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Cannot read properties of undefined (reading 'name')`             | A font declared without a real `typeface` object.                                                                             | Declare `text: { font: { typeface: { name, fonts: [{ uri, subFamily, weight, style }] }, uri } }`.                                                         |
| `The block doesn't have a background color.`                       | `setBackgroundColor` was called on a `page` (or other block kind that lacks the prop).                                        | Pages don't accept `setBackgroundColor`. Use a full-bleed `graphic` block with a color fill instead.                                                       |
| Text block exists with correct geometry but **glyphs don't draw**  | The font resource never loaded: hand-built/hardcoded font URI, or a typeface whose `fonts[]` lacks the selected weight/style. | Look the typeface up from `ly.img.gfonts` inside `edit` (design-rules.md §6.7) instead of hardcoding URIs, then `await forceLoadResources` before capture. |
| `Couldn't find property "<name>" on block.`                        | Property doesn't exist on this block type, or you guessed the property name.                                                  | Look up the block type's `props` tree in `../api/SKILL.md` for the exact property name and which block types accept it.                                      |
| `Invalid color reference …`                                        | A color/fill value was written without a fill attached.                                                                       | Assign a spec: `setProps(block, { fill: { type: 'color', color: { value: {r,g,b,a} } } })`.                                                                |
| `Setting the "text/fontFileUri" property directly is unsupported.` | Tried to write `text/fontFileUri` directly instead of declaring `text.font`.                                                  | Always declare `text: { font: { family, weight } }` (or `{ typeface, uri }`). There is no shortcut.                                                                                      |
| `EngineError is not defined`                                        | There is no `EngineError` in `edit`'s scope, and the engine's errors are not instances of an exported class.                 | Branch on `e.code` (`'BLOCK.UNKNOWN'`); see **Catching an engine error** below.                                                                            |

## Catching an engine error — branch on `e.code`, not `instanceof`

There is no `EngineError` in `edit`'s scope, and what the engine throws is an `Error` whose class is not exported, so `e instanceof EngineError` cannot work. The contract is `e.code`: an error the engine throws, directly or through `engine.design`, carries `code` (`'BLOCK.UNKNOWN'`), `category` (`'BLOCK'`), a `hint` that says what to do, and the name `EngineError [<code>]`. An error `engine.design` raises itself has no `code`, and neither do the few engine errors it rewraps to name what is valid (an unknown fill or shape type, a failed font-metrics fetch): read their message.

```js
try {
  await engine.design.destroy(id);
} catch (e) {
  if (e.code !== 'BLOCK.UNKNOWN') throw e;
  // the block was already gone
}
```

## Finding a block by its copy — use `findText`, not `===`

Your `edit` code runs with `engine` **plus two helpers**: `findText(copy)` returns the one text block whose copy matches, `findAllText(copy)` returns every match (`[]` for none).

Customer scenes have unnamed blocks, so "the headline" is only reachable by its text — and a hand-rolled walk comparing each block's text to `'Headline'` is one of the most common ways an `edit` throws. The string on the page is rarely the string in the brief:

| Symptom                                                | Cause                                                                |
| ------------------------------------------------------ | -------------------------------------------------------------------- |
| A lookup for copy you can SEE on the page matches zero | Trailing/leading space on the block (`"ORIGINAL "`).                 |
| A lookup with a currency or percent sign matches zero  | The design sets NBSP before `€`/`%`, your literal has a plain space. |

```js
const headline = findText('ORIGINAL'); // matches "ORIGINAL " (trailing space)
const price = findText('For everything above 49,99 €'); // matches an NBSP before €
await engine.design.setProps(headline, { text: { string: '오리지널' } });
```

Matching folds NBSP / narrow-NBSP / thin space and trims the ends; it is otherwise **exact**, so case and inner punctuation still distinguish blocks. `findText` throws when the match isn't unique, and the error **lists the copy actually on the page** — read it rather than guessing again.

When a new error type shows up, isolate it with **one** small `edit` (a single block, the failing call), not a series of trial-and-error rebuilds. For the authoritative TypeScript signature, look the member up in `../api/SKILL.md` (upstream core: `../api/signatures.d.ts`).

## Runtime quirks

These are **runtime semantics that don't show up in the .d.ts**. Check this list before re-bisecting.

| Symptom                                                                                                                                                                                                                                                             | What's happening                                                                                                                                                                                                                          | Workaround                                                                                                                                                                                                                                                                                                                                                                                                                          |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A `text.font` declaration with a new uri doesn't change the rendered font on an existing block.                                                                                                                                                                     | Engine treats two typeface objects with the same `name` as identical and skips the swap.                                                                                                                                                  | Use a unique `name` per swap (e.g. `"Playfair Display v2"`), OR delete and recreate that single block with the new font.                                                                                                                                                                                                                                                                                                            |
| Text doesn't reflow after a raw font/size write. Old glyph layout sticks.                                                                                                                                                                                           | The text shape is cached and only invalidated when the string content changes.                                                                                                                                                            | Write font/size through `await engine.design.setProps(id, { text: … })` — it forces the re-shape AND preserves every per-character style range (capture → re-set string → replay) automatically.                                                                  |
| Ring/curved text renders at ~half the authored path size, or centering offsets seem to need magic factors.                                                                                                                                                          | The engine normalizes the path and fits its bbox to the block frame; with an Auto box the authored size is lost, and offset math against the authored radius no longer lines up.                                                          | Set the path, then an ABSOLUTE frame at the intended ring size (width = height = D). The ring then renders at exactly D and `pathOffset` is a plain 0..1 arc fraction from the path's `M` point — full recipe in design-rules §6.5.4.                                                                                                                                                                                               |
| Text block exists with the right font, string, size, and position — but glyphs don't draw.                                                                                                                                                                          | Block height is too small for the font's ascender + descender extent. The engine silently drops the render rather than overflowing or clipping.                                                                                           | Set height ≥ `fontSize × 1.6` for sans-serif body, `≥ 1.8` (better 2.0) for display serifs (Playfair, Cormorant) and scripts (Great Vibes, Caveat). Or use Auto + getFrameWidth (SKILL.md §4).                                                                                                                                                                                                                                      |
| `getProps(id, ['width', 'height'])` returns `0` on an Auto-sized text block. Tempting to read this as "font didn't load → text broken".                                                                                                                                 | `width`/`height` are what you set; in Auto mode that's `0`. They are **not** measurement APIs and **not** a font-load signal.                                                                                                    | Use `await engine.design.measure(id)` for the measured shaped extent. `measure(id).width > 0` is the actual "font loaded + shaped" probe.                                                                                                                                                                                                                                                                     |
| Anthropic returns `400 ... image dimensions exceed max allowed size for many-image requests: 2000 pixels`.                                                                                                                                                          | An image from something other than `preview` (e.g. an image your edit `code` returned inline) exceeded 2000 px on a dimension. `preview` itself is capped at 0.25 megapixels and 1568 px per dimension, so it can no longer trigger this. | Check images your own `code` returns inline; keep them under 2000 px per dimension. For seeing your work, prefer `preview` — every image it returns is always within limits, however many blocks you ask for.                                                                                                                                                                                                                       |
| Accent shape covers text it should sit behind (pill hides headline; frame hides photo edge).                                                                                                                                                                        | Child block created and appended AFTER the block it should sit under. `appendChild` places later children on top — there is no z-index property.                                                                                          | Create the background shape first, append it, THEN create+append the foreground text. To fix an existing scene without destroying anything: `await engine.design.insertChild(page, bgId, 0)` to push back-most, or insert before a sibling via `(await engine.design.getChildren(page)).indexOf(siblingId)`. See SKILL.md §4 "Z-order via child order".                                                                                          |
| Resizing a block with an image fill silently crops the subject out — the face/product that was centered drifts to an edge or off-frame after a width/height change.                                                                                                 | The fill shows a _window_ onto its source; a `Cover` fill recomputes that window from the block's new **aspect** and re-centers, a `Crop` fill exposes gaps. The block frame is right; the region of interest moved.                      | Capture the fill's ROI **before** the resize (`getProps(id, ['contentFill', 'crop'])` — `crop.scaleRatio`, `translationX/Y`, `rotation`) and re-apply **after**, using `adjustCropToFillFrame(id, sr)` to refill gaps. Never write `crop: null` in a resize path — it forces the mode back to `Cover`. Full routine: `resize` skill, "Preserve the region of interest". |
| A track child's `playback.timeOffset` "doesn't stick" — a video/shape renders at the wrong moment, or clips with deliberately overlapping offsets (for a crossfade) instead play back-to-back with a hard cut and no overlap. | `track/automaticallyManageBlockOffsets` defaults to `true`. The track auto-arranges its children back-to-back by cumulative duration and silently overwrites any manual `timeOffset` — no error. Coincidentally correct with a single child at offset 0, which is why it hides until you need custom/overlapping timing. | `await engine.design.setProps(track, { track: { automaticallyManageBlockOffsets: false } })` right after creating the track, before setting any child's `playback.timeOffset`. Verify with `getProps(child, ['playback'])` if in doubt. |

## Diagnosis order — text doesn't render

Cheap → expensive:

1. **Did you await fonts?** — `await engine.design.loadResources([page])` inside the same edit before measuring. (Capturing is covered: `preview`, `export`, and the commit itself run this barrier server-side.)
2. **Height vs font size** — `measure(id).height >= parseFloat(getProps(id, ['text.fontSize']).text.fontSize) * 1.6`?
3. **Position on page** — block within `[0, pageWidth] × [0, pageHeight]`?
4. **Font URI valid** — was `text.font` declared by `family` (§6.7), or — for a brand file imported with `asset_add` — with that returned `uri`? Never a hand-built typeface with a guessed URI.

After `loadResources`, every text block's `measure(id).width` is its shaped width. If that's still `0`, the URI didn't deliver a renderable font — look the typeface up from `ly.img.gfonts` instead of hardcoding a URI (design-rules.md §6.7).
